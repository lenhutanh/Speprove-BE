# Module Layout: File Mapping

> Generated by the move script on 2026-11-27 from the rules of [the design](./design.md), sections 3 and 4, with one later correction (see below). Paths are relative to `src/`. 337 files: 298 move and 39 stay in place (`index.ts`, `scripts/`, `types/`, and the files that already sit in their target folder). Read it once before the moves; a wrong line is fixed in the rules, not in the branches.

> **Correction of 2026-11-27:** `vocabulary-extraction.service.ts` was first placed in `content/vocabulary/` because of its name, but it reads the attempts of the learners, so it moved to `practice/jobs/` next to the vocabulary extractor adapter (checkpoint `layout-vocabulary-extraction`).

> **Correction of 2026-11-28:** the table is the whole move, in one step from the old path to the final path. It includes the decision to keep no layer folder inside a module: the files of `repositories/`, `types/` and `services/` sit in the folder of their module or entity, `payment/providers/` became `payment/adapters/`, and three files changed a name (`queue.constants.ts`, `rate-limiter.type.ts`, `speaking.job.type.ts`).

> **Correction of 2026-11-28 (second):** the socket ticket check moved to `auth/socket-auth.middleware.ts`, `SOCKET_EVENTS` to `assessment/assessment.constants.ts`, the LLM vocabulary extractor to `practice/adapters/vocabulary-extractor/`, and `health.router.ts` became `health.route.ts`.

> **Correction of 2026-11-28 (third):** the whole of `core/security/` stays together (the token interface, `TokenService`, the token payload, the password hasher, the token duration helper), with `.interface.ts` in place of `.contract.ts`. `core/queue/` is flat (the `workers/` folder is gone), and `bull-board.ts` moved to `main/` because only `index.ts` calls it. `status.constants.ts` moved to `core/persistence/`. Four files were removed: the three unused `index.ts` barrels of `security`, `rate-limiter` and `queue/workers`, and `async-handler.ts`, whose 7 lines are now inside `bind-handler.ts`. One file was added: `modules/assessment/assessment.di.ts`, so the speech and LLM providers are registered like those of every other module.

> **Correction of 2026-11-28 (fourth):** eight files got a name that matches what they hold. `groq.llm.ts`, `groq.stt.ts` and `azure.assessment.ts` became `groq-llm.provider.ts`, `groq-stt.provider.ts` and `azure-pronunciation.provider.ts` (their classes are `*Provider`, like the seven other files of that kind); `query-builder.ts` became `query.builder.ts` (same form as the other builders); the two `prompt.builder.ts` and the two `response.parser.ts` got the name of their adapter, so no two files share a name.

> **Correction of 2026-11-28 (fifth):** the 15 barrel files (`index.ts` that only re-export) are gone: `config`, `core/{cache,errors,http,middlewares,persistence,queue,types,utils}`, `modules/{account,auth,notification}` and the three of the adapter folders. Every import names the file that holds the name. Only `src/index.ts` (the entry point) and `main/routes.ts` keep that name or role.

> **Correction of 2026-11-28 (sixth):** names that did not say what the file holds were changed: `queue.factory.ts` and `worker.factory.ts` are `queue.registry.ts` and `worker.registry.ts` (they keep a map and create nothing; the classes are `QueueRegistry` and `WorkerRegistry`), `livekit.service.ts` is `livekit.provider.ts` (`LiveKitProvider`, an adapter of an outside system), `cache.interface.ts` is `cache.service.interface.ts` (the interface of `cache.service.ts`), and `rate-limiter.middleware.ts` sits in `core/middlewares/` with the other middlewares.

> **Correction of 2026-11-28 (seventh):** one naming rule was applied to every class, interface and constant (see `docs/07-development-guides/01-coding-standards.md`, 3.2 and 3.7). Ten files changed name so that the file is `<name>.<last word of the class>.ts` and the interface file is `<name>.<role>.interface.ts`: `password.hasher.ts`, `llm.evaluator.ts`, `llm-vocabulary.extractor.ts`, `azure-pronunciation-assessment.provider.ts`, `token.service.interface.ts`, `llm.provider.interface.ts`, `stt.provider.interface.ts`, `pronunciation-assessment.provider.interface.ts`, `payment.provider.interface.ts` (it was `base.provider.ts` and holds only the interface), and `error.constants.ts`. The technology is not in the name of a class that has only one implementation: `PasswordHasher` (bcrypt), `TokenService` (JWT) and `CacheService` (Redis); `IHasher` is `IPasswordHasher`, and the last word of every interface name is in its file name (`vocabulary.extractor.interface.ts`).

> **Correction of 2026-11-28 (eighth):** the part of a file name after the dot is a role of the system, never a word taken from the name. Allowed roles: `controller`, `route`, `service`, `repository`, `model`, `dto`, `validation`, `mapper`, `middleware`, `di`, `constants`, `type`, `util`, `provider`, `config`, `socket`, `error`, `producer`, `consumer`, plus the patterns `builder`, `parser` and `registry`, which several files use. Eleven files changed: `password-hasher.service.ts` (with its interface), `llm-evaluator.service.ts`, `rule-based-scorer.service.ts`, `llm-vocabulary-extractor.service.ts` (with its interface), `di.constants.ts`, `speaking-job.type.ts`, `payment-provider.registry.ts` (`PaymentProviderRegistry`: it looks a provider up by name and creates nothing), `redis-client.util.ts`, `response-transformer.util.ts` and `rubric.constants.ts`. The earlier corrections that name `.hasher`, `.evaluator`, `.extractor`, `.scorer`, `.factory` or `.transformer` are replaced by this one.
