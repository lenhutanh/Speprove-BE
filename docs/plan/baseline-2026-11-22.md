## Dependency vulnerabilities (`pnpm audit`, 2026-11-22)

| Repository | Before | After (lockfile updated within the declared ranges) |
| :--- | :--- | :--- |
| `speprove-be` | 80 (2 critical, 34 high, 40 moderate, 4 low): mongoose, proxy-addr (through express), axios, body-parser, multer, engine.io, socket.io-parser, follow-redirects, form-data, ws, zod, and dev tooling (eslint, nodemon) | 2 moderate: `glob` through `swagger-jsdoc` and `minimatch` through `nodemon` (both dev or documentation tooling) |
| `speprove-fe` | 79 (4 critical, 40 high, 30 moderate, 5 low): `next` 16.1.1 (several critical remote-code-execution and request-bypass advisories, fixed from 16.4.1), sharp, postcss, nanoid, browserslist, js-yaml, zod and others | 0 (`next` 16.4.6) |
| `speprove-testing` | 0 | 0 |

Changes: `pnpm update --lockfile-only` in BE and FE (about 40 direct dependencies moved to newer versions inside their `^` ranges), `next` and `eslint-config-next` pinned to 16.4.6, unused BE dependencies `edge-tts-node`, `msedge-tts`, `morgan`, `@types/morgan` removed. Checked in a throw-away copy with a fresh install (`--ignore-scripts`): BE `tsc` passes and ESLint reports 0 errors (235 warnings); FE `tsc` passes, ESLint reports 0 errors (16 warnings) and `next build --webpack` succeeds. No behaviour test was run (BE has no tests). `node_modules` in the repositories was not touched, so run `pnpm install` on each operating system before using the new lockfile.

## How to refresh

```bash
pnpm lint
npx tsc --noEmit
npx tsc --noEmit --noUnusedLocals --noUnusedParameters
grep -rn ': any\|as any\|<any>' src | wc -l
grep -rn 'console\.\(log\|error\|warn\)' src | wc -l
```

The ESLint complexity numbers, the index count and the module-dependency table come from throw-away scripts described in `docs/specs/architecture-refactor/design.md` §11.3.
